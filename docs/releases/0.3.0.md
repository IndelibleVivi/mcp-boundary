# MCP Boundary 0.3.0

MCP Boundary `0.3.0` packages the expanded MCP engineering skill and its self-contained recipes. These notes describe the source release; the official plugin directory and website have separate publication records in [current state](../current-state.md).

## Changes since 0.2.0

- Bundle dated Skills distribution, Cloudflare authorization/proxy, OpenAI native entrypoint, and Tasks/Events recipes in the one active `$mcp-boundary` skill.
- Keep current extension requirements, the historical OpenAI importer observation, and the current plugin package-review process distinct.
- Add local fixtures and independent checks for all six original core evaluation cases.
- Restore Lab source, packaging, browser, clean-package, and isolated-runtime checks as repository evidence; none of that runtime is distributed in the plugin.
- Move OpenAI presentation into the portable root manifest's inline extension and generate the legacy Codex compatibility manifest from the same source.
- Reduce the short listing description to `MCP work on the live path`, add the public support URL, and publish the updated skills-only version on the existing listing.

The plugin remains one pure skill. It adds no MCP server, app connector, hook, authentication flow, telemetry, hosted service, or runtime dependency.

## Behavior evidence

The October 2026 comparison remains an executed, one-run-per-cell development observation for its three original repair cases:

| Arm | Completed outcomes |
| --- | --- |
| No MCP skill | `2/3` |
| Released `0.2.0` | `3/3` |
| Initial candidate | `3/3` |
| Final candidate follow-up | `3/3` |

The no-skill result missed an optional input-schema repair. The final candidate did not repeat an earlier extra scope question. These results do not establish an incremental completion advantage over `0.2.0`, better general code, lower production rework, or support in any named host.

The six new core cases have fixtures and independent local checks, but **no model results**. Their red/green/partial-repair tests establish that the checker rejects the supplied broken and partial repairs; they do not establish model behavior.

The October treatment was explicit source-file loading through its `SKILL.md`, not installed activation or installed-skill trigger selection. Its saved final context identity is the October snapshot only, not the delivered `0.3.0` skill source. Raw runs and private harness material remain outside this repository.
