BUILD / FROM INTENT TO IMPLEMENTATION

Build the path the caller will use.

Turn the requested capability into a working MCP implementation, with controls at the layer that owns the effect.

TracePin the intended caller, transport and protocol revision.
ImplementImplement the capability on the chosen entrypoint.
VerifyExercise the actual request and returned effect.
PROMPT / $mcp-boundary
Use $mcp-boundary to build the requested MCP capability. Identify the intended caller, entrypoint, transport and protocol revision; implement it on the active path, place controls at the owning layer, and verify the requested behavior. Keep the scope proportional to the task.
REPAIR / FROM SYMPTOM TO CAUSE

Fix the path that actually runs.

Follow the failing call through the selected entrypoint. Repair the owning layer, then reconcile the built artifact with the running process.

TraceLocate the active caller, entrypoint and failure.
ImplementFix the owning layer; rebuild or reactivate as needed.
VerifyReproduce the original call and inspect the effect.
PROMPT / $mcp-boundary
Use $mcp-boundary to repair this MCP integration. Trace the active caller, entrypoint, transport, handler, package and runtime. Implement the fix on that path and run the narrowest check that can reject the original failure. State what remains unverified.
MIGRATE / KEEP THE CALLERS IN VIEW

Move the implementation. Close the old path.

A migration also has callers, packages and runtimes to move. Find the still-active dependencies before retiring superseded behavior.

TraceSelect the target revision and identify active callers.
ImplementMigrate their paths and deliberately retire old behavior.
VerifyTest preserved behavior on the selected artifact and runtime.
PROMPT / $mcp-boundary
Use $mcp-boundary to migrate this MCP implementation to the selected revision. Identify evidenced callers and active entrypoints, implement the migration, deliberately retire superseded paths, and reconcile source, package and runtime. Distinguish local checks from named-host results.
INSPECT / READ-ONLY BY DEFAULT

Know where the behavior is owned.

Inspect the current implementation without editing it. Separate a protocol requirement from transport controls, deployment policy and host behavior.

TracePin the current revision and reachable surface.
InspectLocate the owning layer without modifying the repository.
VerifyReport findings with the observations that support them.
PROMPT / $mcp-boundary
Use $mcp-boundary to inspect this MCP implementation without editing it. Trace the active caller, entrypoint, transport, protocol/SDK dispatch, capability effect, package and runtime. Locate control ownership, report bounded findings, and identify the smallest useful next checks.
VERIFY / ASK AT THE RIGHT BOUNDARY

Test the claim where it can be observed.

Use the exact artifact and observer needed for the claim. A local rendering test has value; a different host still needs its own observation.

DefineDefine the claim, exact artifact and qualifying observer.
ExercisePrepare only the authorized check that can reject it.
RecordRecord the outcome and its remaining limits.
PROMPT / $mcp-boundary
Use $mcp-boundary to verify this MCP behavior. Define the claim, exact artifact, active runtime and qualifying observer. Run authorized checks at the relevant boundary, distinguishing source, process, artifact and named-host observations. Do not promote an unobserved host result into success or failure.

Open stable listing ↗Public source ↗

The listing currently reflects stable 0.1.0. Repository source remains 0.2.0-alpha.1 until a release is deliberately published.

Install from the repository

codex plugin marketplace add IndelibleVivi/mcp-boundary --ref main
codex plugin add mcp-boundary@mcp-boundary

These commands follow main, not a pinned directory release. Restart Codex after installation. A current Codex CLI with Agent Plugin support is required.

What gets installed?

One pure skill with its bundled references and assets. It starts no server, adds no app connector or authentication flow, and sends no analytics or telemetry. The Guide and executable Lab remain repository resources.

How much process does this add?

Only the depth the task needs. A small wording change or local helper does not need an elaborate audit. The skill has an explicit stop rule for small, clear MCP tasks.

What does a successful check establish?

The behavior observed at that boundary. Source, local process, artifact, activated runtime and named-host observations remain distinct. The public library links to the method and runnable checks; this website does not execute them.
