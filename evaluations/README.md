# MCP Boundary behavior evaluations

These cases test whether the installed skill changes material engineering outcomes. Package validity, prose quality, and repository tests are insufficient substitutes.

Run each case under comparable conditions:

1. no MCP skill;
2. the historical `mcp-server-engineering` skill;
3. the candidate `mcp-boundary` skill.

Keep model, tools, permissions, time/turn budget, target revision, and starting fixture fixed. Record raw outputs and repository state before projecting a score.

The rubric rewards completion on the active path, correct ownership, qualifying verification, bounded claims, retirement of unintended old paths, and proportionate scope. Professional-sounding language has no independent score.

A same-owner run is development evidence. It is not independent assurance.
